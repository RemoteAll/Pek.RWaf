# 限流能力全面审计报告（2026-10-25）

> **范围**：`Pek.RWaf::throttle`（接口级限流）、`DH.RustBase::ratelimit`（通用计数引擎）、
> RWaf CC 限流接入、六个消费方编译回归。
> **对照**：C# `G:\Code\Pek.FrameWork\DH.RateLimter`（`RateLimitProcessor` / `ApiThrottleActionFilter` /
> `CacheRateLimitStore` / `Common` / `Valve` / `Enums`）。
> **方法**：逐行代码审查 + C# 语义对照 + 并发/边界用例 + `cargo clippy -D warnings` +
> 全量测试 + 消费方 `cargo check` + Linux musl 交叉检查。
> **结论**：**未发现 P0 阻断问题**；修复 2 类 P1（分片满 O(n) 扫描、热路径重复分配）与若干 P2；
> 残余风险已记录在第 5 节。

## 1. 功能对齐结论

| C# `DH.RateLimter` 能力 | Rust 落点 | 结论 |
| --- | --- | --- |
| `[RateValve]` 多阀门、`Priority` 降序 | `ThrottleRule.valves`（加载/应用配置时归一化排序） | ✅ |
| `Policy` 七种（Ip/User/Header/Query/Path/Cookie/Form） | `Policy` 七种同名 | ✅ |
| `WhenNull.Pass/Intercept` | `WhenNull`（空值跳过 / 按客户端 IP 生成空值标识） | ✅ |
| `Limit` + `Duration`（秒） | `RateValve.limit/duration`；`limit/duration=0` 跳过 | ✅ |
| `IRateLimitStore.IncrementAsync`（Redis/内存） | `dhrust::ratelimit::CounterStore`（默认分片内存，可注入 Redis） | ✅ |
| `ReturnType` 三种 | `ThrottleReturnType`（429 + 对应响应体） | ✅ |
| `Api-Throttle-Status` 请求头 | 同名请求头 + 响应头 | ✅（并回写响应，便于客户端/网关观测） |
| `AllowRateLimter` 全局开关 | `ThrottleConfig.enable` | ✅ |
| `RateLimterOptions` 三个钩子 | `set_user_identity` / `set_client_ip` / `set_limited_response` | ✅ |
| IP→数字、MD5 短值 | `dhrust::net::ip_to_num`、`dhrust::sign::md5_short` | ✅（与 C# 算法一致） |
| Redis 首次创建设过期 | `CounterStore` 契约 + `WindowLimiter` 语义 | ✅（进程内已实现；Redis 适配器待接） |
| 黑白名单 | — | 不实现（C# 源码注释明确“暂未实现”；IP 名单由 WAF 负责） |
| MD5/IP 5 分钟缓存 | — | 有意不做（Rust 单次百纳秒级；避免无界缓存；改为静态部分预计算/单次解析） |

**有意差异**：
1. Rust 无运行时特性/反射 → 用 `Config/Throttle.toml` 规则表或 `Throttle::guard`；
2. `Form` 仅支持 `application/x-www-form-urlencoded`（`Ctx` 已有解析）；multipart 待路由层补齐；
3. `UserIdentity` 默认读 `Ctx.state` 的用户键（`user_id`/`userId`/`userid`/`user`/`username`/`sub`），可用钩子覆盖；
4. 与 C# 共享 Redis 计数时，需把 `keyPrefix` 对齐 `RedisSetting.CacheKeyPrefix`、规则 `name` 对齐
   C# `(DeclaringType.FullName + "." + Method).ToLower()`；策略键/值的 MD5 短哈希口径已一致；
5. WAF CC 窗口锚点由“自然分钟”改为“每 IP 首次命中起 60 秒”（与 `DH.RateLimter` 引擎一致，避免整点突发）。

## 2. 发现与整改

| ID | 级别 | 发现 | 处理 |
| --- | --- | --- | --- |
| AUD-01 | **P1** | `FixedWindowStore` 分片满时 `retain` + `min_by_key` 全表扫描 O(n)。唯一键攻击（大量伪造 IP/头值）填满分片后，每次新键插入都会扫描 8192 项，形成 CPU 热点。 | **已修**：分片满时 O(1) 淘汰任意一个键；`prune_expired()` 保留为显式批量清理。文档注明“内存安全优先”的取舍。 |
| AUD-02 | **P1** | 限流热路径存在重复分配：每次请求 `path.to_ascii_lowercase()`；`{param}` 匹配分配两个 `Vec`；每个阀门重复构建 API 名/前缀；IP 数字在无 IP 阀门时也计算；`client_ip` 每次多取一次配置快照。 | **已修**：路径匹配改为零分配 ASCII 大小写不敏感比较；`{param}` 改迭代器；API 名按需构建一次；仅存在 IP 阀门时转换 IP；`client_ip` 复用当前配置快照。 |
| AUD-03 | **P2** | Query/Form 键名大小写敏感，与 ASP.NET Core 的常见行为不一致（C# `Request.Query/Form` 字典大小写不敏感）。 | **已修**：先精确匹配，再大小写不敏感兜底；新增用例。 |
| AUD-04 | **P2** | 空白策略值（如 Header=`"   "`）与 C# `IsNullOrWhiteSpace` 口径不一致：C# 计数键会省略值段，旧实现会按空白值哈希。 | **已修**：`counter_key` 对空白值省略值段；新增用例。 |
| AUD-05 | **P2** | 直接 `ThrottleConfig::load_merging` 得到的是文件声明顺序，未按 priority 归一化；与 `Throttle` 运行期语义不一致。 | **已修**：`load_file` 加载即归一化；新增双阀门配置往返/排序用例。 |
| AUD-06 | **P2** | `Throttle::guard` 每个请求深拷贝 `ThrottleRule`（含所有阀门字符串）。 | **已修**：规则改为 `Arc<ThrottleRule>` 共享，仅 Arc 克隆。 |
| AUD-07 | **P2** | 配置迁移/缺键补齐/类型修正提示被丢弃，运维看不到自动维护结果。 | **已修**：`load_file` 把 `TomlConfig` notes 写入日志。 |
| AUD-08 | **P3** | WAF CC 窗口语义改变（自然分钟 → 每 key 首次命中 60 秒）。 | **已确认并记录**：这是复用统一引擎的预期变化，避免整点突发；`README`/`middleware.rs`/`config.rs` 文档同步。 |
| AUD-09 | **P3** | WAF CC `Retry-After` 仍固定 60（实际剩余可能更短），因为扩展 `Verdict::Blocked` 会破坏公开枚举匹配。 | **部分改进**：`RateLimiter::check` 返回 `Decision`（含 `reset_in`）供消费方使用；WAF 中间件暂保持 60（上界），列入后续候选。 |
| AUD-10 | **P3** | 计数键使用 64 位 MD5 短哈希，存在碰撞可能（与 C# 一致）。 | **接受**：限流不是鉴权，碰撞只可能导致共享计数；文档注明不要把敏感信息直接放进 `policy_key`。 |
| AUD-11 | **P3** | 分片满时 O(1) 淘汰可能淘汰活跃计数，攻击者可用大量唯一键冲刷。 | **接受**：内存有界优先；限流键应使用 IP/哈希短值等低基数输入；文档记录。 |
| AUD-12 | **P3** | `Form` 仅支持 urlencoded；`multipart/form-data` 返回空值（按 `WhenNull` 处理）。 | **接受并文档化**；待 `dhrust` 路由层支持 multipart 后接入。 |
| AUD-13 | **P3** | 自定义 `set_limited_response` 不会自动补 429/`Retry-After`/`Api-Throttle-Status`。 | **文档化**：自定义响应由调用方负责；默认响应已包含全部头。 |
| AUD-14 | **P3** | 缺少 Redis `CounterStore` 适配器（C# 默认支持 Redis 共享计数）。 | **后续**：`Pek.RRedis` 实现 `CounterStore` 后通过 `Throttle::with_store` 注入；接口与 TTL 语义已定。 |
| AUD-15 | **P3** | 缺少限流观测指标（allow/deny 计数、命中规则分布）。 | **后续**：保持库轻量，暂不加指标；宿主可从日志/响应头采集。 |

## 3. 并发与资源

- `FixedWindowStore`：分片 `Mutex<HashMap>`，按 `fnv1a_64(key)` 分片（CPU 并行度 4~16）；
  递增在锁内完成；8 线程 × 1000 次并发测试计数不丢。
- 分片键数上限默认 8192（总计约 13 万键上限），无后台线程、无周期任务；满时 O(1) 淘汰。
- `Throttle` 配置用 `RwLock<Arc<ThrottleConfig>>` 快照：检查期间不持锁、不阻塞热重载；
  热重载 10 秒 mtime 节流 + CAS 单飞；重载/面板保存后清零计数。
- 热路径分配（审计后）：配置 `Arc` 克隆、客户端 IP 字符串、计数键字符串 + MD5 值哈希、
  响应头字符串；路径匹配/`{param}`/skip 判断零临时分配；`guard` 规则零深拷贝。
- 无新增全局缓存；`ThrottleConfig::config()` 的全量克隆只用于面板/诊断，不在请求路径。

---

## 4. 安全

- `trustForwardedFor` **默认 false**：只有反向代理会覆盖 `X-Forwarded-For`/`X-Real-IP` 时才开启，
  否则客户端可伪造来源绕过限流；新增信任/不信任两组用例。
- 日志只记录规则名、策略名、客户端 IP、计数/上限/窗口，不打印 Header/Cookie/Query 的具体值。
- 计数键中的策略键/值使用 MD5 短哈希；不把敏感信息直接拼入 Redis 键。
- 无效 IP 按 C# 语义交给 `WhenNull`（Pass 跳过 / Intercept 用空值标识继续限流）；新增用例。
- 限流不是鉴权：WAF/鉴权仍应在业务层保留；`UserIdentity` 依赖宿主把认证用户写入 `Ctx.state`。

## 6. 残余风险与后续建议

1. **Redis 共享计数**：`CounterStore` 接口已就绪，建议在 `Pek.RRedis` 实现（`INCR` + 前 3 次 `PEXPIRE` + `PTTL` 作 `reset_in`），并通过 `Throttle::with_store` / `load_with_store` 注入。
2. **multipart 表单**：`Form` 策略目前只覆盖 urlencoded；待 `dhrust` 路由层补齐 multipart。
3. **WAF CC `Retry-After` 精度**：如需精确剩余秒数，可在下一主版本给 `Verdict::Blocked` 增加 `retry_after` 字段（破坏性变更），或让中间件直接使用 `RateLimiter::check` 的 `Decision`。
4. **长稳压测**：本轮为功能/边界/并发正确性验证，未做数小时 soak/百万 QPS 压测；上线前建议按宿主实际流量做一次。
5. **可观测性**：如需命中规则分布/拒绝率指标，建议宿主侧从日志或响应头采集，避免库内引入全局指标状态。
